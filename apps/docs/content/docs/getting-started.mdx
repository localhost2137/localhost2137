localhost2137 requires Node.js 24 or later. This repository and every documented workflow use pnpm.

## Try the repository today

The workspace packages are currently private and unpublished. A registry install is therefore not a
runnable evaluation path yet. From a checkout of this repository, run the Stripe SDK example:

```sh
pnpm install
pnpm --filter @localhost2137/example-stripe-sdk test
```

That test starts a temporary runtime, drives the emulator through the official Stripe SDK, advances
its clock, and cleans up the instance. The repository also contains checked-in Slack and
parallel-worker examples.

## Install after publication

After the packages are published, add the runtime and whichever emulator plugin your application
needs. Slack is used here because it has a small setup surface; it is one plugin, not a special
runtime mode.

```sh
pnpm add -D localhost2137 @localhost2137/slack
```

Create `localhost.config.ts` manually using the next section. `pnpm exec localhost init` is a
reviewed documentation-first command and is not implemented in the current CLI. When implemented,
it will create that file only when absent, add `.localhost2137/` to `.gitignore`, avoid choosing or
installing plugins, and refuse to replace an existing config.

If the project uses a TypeScript config, its package must use ESM (`"type": "module"`). A project
that must remain CommonJS can use `localhost.config.mjs` instead.

## Configure a service

Configuration is ordinary TypeScript. Credentials below are deliberately local world data, not real
secrets.

```ts title="localhost.config.ts"
import { slack } from "@localhost2137/slack";
import { defineConfig } from "localhost2137";

export default defineConfig({
  services: {
    slack: slack({
      config: {
        workspaceName: "Local development",
        botToken: "xoxb-local-development",
        signingSecret: "local-signing-secret",
        eventsUrl: null,
      },
    }),
  },
});
```

The key `slack` is the service identity. It appears in routes, CLI commands, storage, and typed
instance handles.

## Start an empty world

```sh
pnpm exec localhost dev
```

The daemon creates the persistent `dev` instance only when absent, starts configured services, and
writes app-facing connection variables to `.localhost2137/.env`. A new instance is empty except for
plugin-required identities. Later starts preserve its state until an explicit reset, and declared
seed data is never applied during normal startup.

In another terminal, inspect the plugin's actual control surface:

```sh
pnpm exec localhost exec slack --help
pnpm exec localhost describe slack --json
```

Then create state through operations:

```sh
pnpm exec localhost exec slack create-user --name Ada --json
pnpm exec localhost exec slack create-channel --name general --json
pnpm exec localhost exec slack add-user-to-channel \
  --channel general --user Ada --json
```

Your application should continue using its normal provider SDK or HTTP adapter. Point that boundary
at the plugin connection values; do not replace application behavior with control operations.

## Clone an example after the command ships

The reviewed demo-clone contract is also not implemented in the current CLI:

```sh
pnpm exec localhost demo clone slack-ping-bot ./slack-ping-bot
cd ./slack-ping-bot
pnpm test
```

`localhost demo clone <name> [directory]` will create a standalone copy in a new or empty directory,
install it with pnpm, and refuse to overwrite existing files. `slack-ping-bot` uses the official
Slack Bolt SDK and a signed local Events API callback. Until that command ships, run the checked-in
workspace example instead:

```sh
pnpm --filter @localhost2137/example-slack-ping-bot test
```
